> ```python

> 适配器路由依赖 `prepared_input` 参数来判断是否使用 Docker 引擎，但 `execute(run, {})` 传入的 context 为空，且 `prepare()` 生成的 `run.input` 未包含适配器路由所需的字段格式（如 `system_type`、`structure_data`、`input_file`），导致适配器始终回退到占位实现。

## 六、结论与建议

### 核心问题
**7 个"假成功"服务在 HTTP API 层面仍未真正接入科学计算引擎**。此前的修复停留在 application.py 的适配器路由代码，但 API 路由层（scientific_routes/*.py）的调用方式未将请求参数传递到适配器路由，导致所有调用回退到占位实现。

### 修复建议
1. **修改 API 路由层**：将请求参数（如 `input_file`、`system_type`、`structure_data`、`compound_name`、`module` 等）通过 `prepared_input` 或 `context` 传递给 `execute()`，确保适配器路由能识别输入类型并选择正确的引擎。
2. **或修改 application.execute**：从 `run.input` 中提取适配器路由所需的字段，而非依赖外部传入的 context。
3. **添加集成测试**：在测试套件中添加通过 HTTP API 调用的端到端测试，验证返回内容不含占位符，避免"单元测试通过但 API 返回占位"的问题。
