## 1. 执行摘要

### 1.1 当前产品阶段判断

BatteryEMCL Lab 当前处于 **内部 PoC（概念验证）向受控试点过渡** 阶段。系统架构完整、AI 可信度框架已建立、核心研发链路（项目 → 候选 → 预测 → 实验任务 → 样品）基本可跑通，但 **3 个 P0 阻断性问题** 导致数据治理链路无法闭环：

1. **物料规格库列表渲染崩溃**（`toFixed` 调用 undefined），直接影响配方/BOM 的原料选择、成本核算与合规检查；
2. **设备台账新增设备无法完成**，导致实验任务无法关联真实设备；
3. **数据接入 CSV 导入流程无法完成**，导致湿实验数据无法批量进入系统。

在 v8 整改基础上，UI/UX 层面的英文枚举、空态引导、禁用按钮 tooltip、表格视觉层级等问题已得到明显改善；但上述 P0 问题仍未根除，系统尚不能供真实新材料团队日常稳定使用。

### 1.2 最值得保留的产品亮点

1. **AI 输出可信度框架**：候选生成、性质预测、配方生成等接口均返回 `confidence`、`key_assumptions`、`evidence_sources`、`human_review_required` 及顶层 `ai_meta`，满足材料研发可审计与可追溯要求。
2. **实验任务幂等保护**：`idempotency_key` 机制有效防止重复提交，实测重复请求返回 `duplicated: true` 与同一 `EXP_` 编号。
3. **项目-任务-样品数据血缘**：实验任务强制校验 `project_id`，样品创建可自动带入 `order_id`，从机制上避免孤儿数据。
4. **Agent-工具-能力契约治理链**：工具与连接器、调用关系、能力契约、智能编排等页面可观察到 Activity → Agent → Tool/Skill/SCP 的映射关系。
5. **SCP 外部工具真实可用**：InternLM、SCP 化学工具、ASKCOS 逆合成、NameToSMILES 等均实测可调用。

### 1.3 最影响客户信任的 P0/P1 问题

| 编号 | 问题 | 影响 |
|------|------|------|
| BEMCL-MAT-P0-001 | 物料规格库列表因 `toFixed` 调用 undefined 崩溃 | 配方/BOM/成本核算原料选择断裂 |
| BEMCL-EQ-P0-001 | 设备台账新增设备无法完成 | 实验任务无法关联设备，设备主数据失效 |
| BEMCL-INGEST-P0-001 | 数据接入 CSV 导入无法完成 | 湿实验数据无法批量进入，数据治理闭环断裂 |
| BEMCL-UI-P1-001 | `DisabledButton` 组件 `null key` 错误跨页面复现 | 多处页面渲染异常、控制台报错、按钮状态不可解释 |
| BEMCL-ECML-P1-001 | ECML 运行 API 超时（>3 分钟） | 实验闭环迭代无法收敛 |
| BEMCL-AI-P1-001 | AI 候选生成化学式不规范（La3O、Li2O3 等） | 下游预测与合成可能基于无效化学式 |

### 1.4 建议整改策略

采取 **"先止血、再闭环、后体验"** 的分阶段策略：

1. **阶段 0（P0 止血，1-2 天）**：修复 `toFixed`/`null key` 等前端渲染错误，恢复物料/设备/数据接入创建功能；
2. **阶段 1（主链路打通，3-5 天）**：验证项目 → 候选 → 预测 → 实验 → 样品 → 数据 → ECML 完整闭环；
3. **阶段 2（数据治理与可信度，5-7 天）**：统一字段映射、校验规则、版本控制、AI 证据与人工责任；
4. **阶段 3（UI/UX 与可观测性，7-10 天）**：按角色重构信息架构、优化异步任务状态与空态引导。

## 2. 测试方法、环境与局限

### 2.1 证据分级规则

- **[已实操验证]**：通过浏览器真实操作或接口调用获得可观察结果，附证据编号 `EV-YYYYMMDD-序号`。
- **[高概率推断]**：有 UI、接口响应、数据模型或一致性迹象，但未能完成完整验证；写明推断依据。
- **[待确认]**：受权限、环境、数据、外部依赖或时间限制影响，无法判断；列出最小补测条件。

### 2.2 环境、权限、外部服务与数据限制

- **环境**：本地开发环境，前后端同源跨域未启用，使用管理员账号，可访问全部菜单。
- **外部服务**：Materials Project API、InternLM、LongCat、SCP 平台（浙江大学等）、ASKCOS 已配置并可连通；VASP/PySCF/M3GNet/LAMMPS 等专家模型与 DFT 计算无可用远程服务器，相关功能按灰化/扩展项处理。
- **数据限制**：未创建破坏性测试数据；所有测试对象使用 `EV-`/`ASSB-`/`PEO-` 等可追溯前缀。

### 2.3 未验证清单及最小补测条件

## 4. 端到端研发闭环验证

### 4.1 材料发现到实验闭环

**操作步骤**：

1. 在 `/projects/new` 输入目标：硫化物固态电解质，25 C 离子电导率 ≥ 1.0e-3 S/cm，调用 AI 拆解生成任务；
2. 在 `/workbench` 选择项目 `ASSB-LPSCl-2026Q3`，调用首席材料学家 Agent 生成候选；
3. 在 `/prediction` 输入 `Li6PS5Cl` 进行性质预测；
4. 在 `/experiment-workbench` 创建实验任务，project_id 自动带入；
5. 在 `/samples` 创建样品，source_order_id 自动带入。

**成功节点**：

- 项目创建 → 201，重复名检测 409；
- 候选生成 → 200，返回完整 `ai_meta`；
- 性质预测 → 200，返回 `ionic_conductivity` 与置信度；
- 实验任务创建 → 200，幂等保护生效；
- 样品创建 → 201。

**失败节点**：

- 设备创建 → 表单无法完成保存（见 BEMCL-EQ-P0-001）；
- ECML 运行 → `POST /ecml/run_step` 超时 3 分 10 秒（见 BEMCL-ECML-P1-001）。

**数据断点**：

- 候选 → 实验任务的 `candidate_id` 自动关联：前端通过路由参数传递，后端支持，但实测中未验证自动填充；

## 6. 页面级深度问题清单

### [BEMCL-MAT-P0-001] 物料规格库 - 列表渲染因 `toFixed` 调用 undefined 崩溃

- **证据状态**：[已实操验证]
- **优先级**：P0
- **问题类型**：功能 / 数据 / 前端
- **证据编号**：EV-20260728-017
- **位置**：数据与知识 > 物料规格库 `/materials` > 物料清单表格
- **触发前提**：管理员账号，访问物料规格库页面即可触发
- **复现步骤**：
  1. 登录系统；
  2. 进入左侧菜单「数据与知识 > 物料规格库」；
  3. 页面表格区域渲染异常，浏览器控制台报错。
- **输入与对象**：列表包含 18 条既有物料，如 `RM-001` / PEO 等
- **预期表现**：表格正常渲染，单价为空时显示 "-" 或 "0.0"
- **实际表现**：控制台出现 `[pageerror] TypeError: Cannot read properties of undefined (reading 'toFixed')`，页面局部白屏/卡顿
- **用户影响**：用户无法查看、新增或编辑物料，配方/BOM/成本核算原料选择断裂
- **研发/合规影响**：物料主数据维护失效，REACH/SDS/COA 合规证据无法录入
- **根因假设**：前端 `RawMaterials.vue` 使用 `record.cost_per_kg.toFixed(1)`，但后端返回字段为 `unit_cost`，导致 `cost_per_kg` 为 undefined

## 9. 视觉设计系统建议

### 9.1 产品视觉定位

- 面向工业研发的深色/浅色双主题，主色为科技蓝（#1677FF），辅色为橙（#FA8C16）用于警示/强调，成功绿（#52C41A），错误红（#F5222D）。
- 避免强 AI 感渐变，保持专业、克制、信息密度高。

### 9.2 字体、字号、行高、间距

- 字体：系统默认无衬线字体 + 等宽字体用于数值/代码
- 标题：20px/28px/36px，行高 1.4
- 正文：14px，行高 1.6
- 表格：12-13px，行高 44px
- 间距：8px 基准单位，卡片内边距 16-24px

### 9.3 卡片/表格/图表/状态徽标

- 卡片：白色背景，1px 浅灰边框，4-6px 圆角，细微阴影
- 表格：斑马纹可选，固定表头，操作列 sticky right
- 图表：使用 ECharts/AntV，统一色板，图例说明数据来源与单位
- 状态徽标：使用面性 tag，文字居中，避免低饱和度色条

### 9.4 化学式上下标、科学计数法、单位、精度规范

- 化学式自动渲染上下标（如 Li₆PS₅Cl）
- 科学计数法统一为 `1.35×10⁻³ S/cm`
- 数值保留有效位 3-4 位，避免无意义精度
- 单位与数值同行显示，避免歧义

### 9.5 禁止视觉模式

- 禁止大面积高饱和度渐变背景
- 禁止低对比度文字
- 禁止图标与文字无对应 tooltip
- 禁止表格操作按钮堆砌

## 10. 数据模型、治理与 AI 可信度整改

### 10.1 核心对象关系与外键

- 项目 `projects` → 任务 `project_tasks` → 实验任务 `experiment_orders` → 样品 `samples` → 实验数据 `experiment_result_records`
- 候选 `candidates` → 配方 `formulas` / BOM → 物料 `raw_materials`
- 设备 `equipment` → 实验任务/数据
- 当前问题：`raw_materials.category` 与 `equipment.category` 的 FK 约束指向错误 schema，需修复为 `mdm.classifications(code)`。

### 10.2 唯一标识、状态、版本、来源、审计字段

- 所有主数据对象必须有 `created_at`、`updated_at`、`created_by`、`updated_by`、`version`。
- 实验任务、样品、配方必须支持版本链，复制新版本时保留来源 ID。
- 删除/归档必须软删除，保留审计日志。

### 10.3 删除/修改保护、幂等与去重、统计口径、数据质量、血缘

## 14. 最终交付判断

### 14.1 能否供真实新材料团队日常使用

**当前判断：否，仅能在受控试点条件下使用。**

可受控试点的条件：
- 完成阶段 0（P0 止血），修复物料、设备、数据接入创建功能；
- 完成阶段 1，验证主研发链路完整闭环；
- 明确 ECML 与 DFT/专家模型的能力边界，不对外承诺未验证功能；
- 配备技术支持人员，处理前端报错与数据异常。

### 14.2 最优先的 10 项整改

1. 修复物料规格库 `toFixed` 渲染错误（TASK-001）
2. 修复设备台账新增设备（TASK-002）
3. 修复数据接入 CSV 导入（TASK-003）
4. 修复 `DisabledButton` null key 跨页面报错（TASK-004）
5. 修复 ECML 运行超时与前置校验（TASK-005）
6. 增加 AI 候选生成化学式校验（TASK-006）
7. 统一主数据 FK schema（物料/设备分类）
8. 补全空态引导与下一步行动
9. 完善异步任务状态与取消/重试
10. 增加输入/输出快照与 AI 调用链审计

### 14.3 应保留深化的功能

- AI 输出可信度框架（`ai_meta`、置信度、假设、证据、人工复核）
- 实验任务幂等保护
- 项目-任务-样品数据血缘
- Agent-工具-能力契约治理链
- SCP/ASKCOS 外部工具集成

### 14.4 应合并、隐藏、降级或暂缓的功能

- **应暂缓**：真实 DFT/VASP/PySCF/M3GNet 计算（无可用远程计算节点，当前仅灰化展示）
- **应明确边界**：智能编排/研发工作台（当前为演示入口，需明确与项目/候选/实验的联动规则）
- **应合并**：部分重复的数据看板（管理看板、控制平面、预算看板信息有重叠，可按角色聚合）

### 14.5 未满足哪些验收条件前，不得对外宣称"AI 驱动研发闭环"

1. 无法从项目正查至候选、预测、实验、样品、数据、ECML 推荐；
2. 无法从结果反查至项目、候选、预测模型版本、实验、设备、样品、QC 规则；
3. 主数据（物料、设备）无法创建，数据无法批量导入；
4. AI 输出未经过校验与人工复核即可进入下游流程；
5. ECML 无法在合理时间内收敛或给出明确反馈；
6. 外部工具调用链不可观测、不可审计。
