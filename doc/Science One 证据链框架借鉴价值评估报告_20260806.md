# Science One 证据链框架借鉴价值评估报告

> 评估日期：2026-08-06
> 对标对象：Google [Science One 框架](https://research.google/blog/science-one-framework-a-verifiable-autonomous-research-framework-via-chain-of-evidence/)（Chain-of-Evidence 证据链 + CoE Audit 审计协议）
> 辅助参照系：Biomni 项目（`D:\Biomni\Biomni`）的文件/文献检索实现
> 评估目的：产出「可借鉴清单 + 差距分析」，判断该框架对本系统（Battery Materials Agent）的借鉴价值。**本轮不改代码。**

---

## 0. 结论速览

**有借鉴价值，且价值集中在「架构层思想」而非「功能点」。** 本系统已具备"声明→证据→审计"的骨架，但这条链路存在两处结构性断裂，与 Science One 的核心主张（可验证性必须是一等架构约束）恰好形成对照：

1. **证据真实性依赖工具自报**：委员会打分卡完整采信 `EvidenceItem` 的 `score`，无独立核验（验证1）。
2. **方法声明与数据源不完全对齐**：科学服务在真实引擎未命中时静默回退内置库，且 `source` 字段不区分真实引擎与兜底来源（验证2）。
3. **引用了无核验环节**：文献通道真实但受噪音污染，无过滤/引用核验（验证3）。

**最值得借鉴的三点**：① 声明→证据的「产生时绑定」设计；② 独立的声明核验器（Claim Verifier）；③ CoE Audit 的事后自动化审计。三者中，③ 与本系统已有 `evals` 高度同构，落地成本最低、优先级最高。

## 1. 评估框架与方法

### 1.1 两层标尺

按文章原意，用两层结构评估本系统：

| 层 | 标尺 | 回答的问题 |
|---|---|---|
| **架构层** | CoE 两原则：**完备性**（每个声明都带证据链）、**正确性**（证据链真能支撑声明） | 证据链是否从设计源头闭环 |
| **执行层** | CoE Audit 四项：**分数核验**、**规格违规**、**引用核验**、**方法-代码对齐** | 对应的核验能力我们有没有 |

### 1.2 呈现方式

每个环节 × 每个标尺给 **三级判定**：`已闭环` / `部分` / `缺失`，附一句话依据。

### 1.3 动态抽查

按约定，从静态判定为「部分/缺失」的环节池中**自动随机抽取 3 个**做运行验证（非人工挑选）：

- 抽取池：`文献调研-引用核验`、`科学服务-方法代码对齐`、`委员会-证据真实性`、`控制平面-证据链粒度`、`审计-引用核验`、`审计-方法代码对齐`
- **随机抽取结果**：`科学服务-方法代码对齐`、`文献调研-引用核验`、`委员会-证据真实性`

> 运行环境说明：本系统真实科学引擎安装于系统 Python 3.10（`chemicals 1.5.2` / `thermo`，已确认可用）；TRAE 自带 vm Python 未装这些库，故动态验证使用系统 Python 3.10 执行。

## 2. 全链路差距评估表

评估覆盖五个环节：文献调研 → 科学服务 → 委员会 → 控制平面 → 审计。

| 环节 | CoE 架构层（完备性/正确性） | CoE Audit 执行层 | 判定 |
|---|---|---|---|
| **文献调研** | **部分**。多源检索（Semantic Scholar/Crossref/LLM/SCP/本地库）真实存在，引用来自 API 可溯源；但无"每声明精读全文并锚定引用"的机制，检索结果直接进入下游 | **部分**（引用核验）。无引用核验/过滤环节，检索噪音（如 Crossref 审稿评论）会进入结果 | 部分 |
| **科学服务** | **部分**。`EvidencePackage` 结构完备（claim/value/confidence/method/source），证据在 `postprocess` 产生时即落库（满足"产生时绑定"）；但 `source` 不区分真实引擎与兜底来源，正确性弱 | **部分**（方法-代码对齐）。真实引擎（chemicals/thermo）已接入，但引擎未命中时静默回退内置库 | 部分 |
| **委员会** | **部分**。`CommitteeVerifier` 用评分卡对证据打分，有覆盖检查；但核验完全采信 `EvidenceItem` 自报分数，无独立真实性核验 | **缺失**（规格违规/分数核验）。打分卡不验证分数是否真实计算得出 | 缺失 |
| **控制平面** | **部分**。`ProvenanceGraph` 记录实体来源（tool/model/human/committee）+ 关系边，可向上游溯源；但证据链粒度是"实体级"而非"声明级" | **部分**（分数核验）。`input_hash`/`output_artifact_path` 记录了输入输出，但未用于事后复现分数 | 部分 |
| **审计** | **部分**。`AuditStore` 追加式记录外部调用（含 input_full/input_sha256），`evals` 用 golden set 回放打分 | **部分**（引用/方法对齐）。有一次性测评（8月报告）但非系统化事后审计；`evals` 偏重"结果正确性"而非"证据链完整性" | 部分 |

## 3. 动态抽查结果（随机抽 3 个）

### 3.1 验证 1：委员会-证据真实性

**构造用例**：向 `CrystalConstructionScorecard` 注入不同真实性的证据。

- 场景 A：模拟分支证据（`status='unknown'`, `score=0.5`）→ 打分卡拦截（`missing_evidence`），说明**模拟分支会被覆盖检查拦截** ✅
- 场景 B：标记 `status='success'` 但分数为硬编码假值（`score=0.95`）→ 打分卡**直接通过**（`passed=true, score=0.95`）❌

**结论**：打分卡完整采信工具自报分数，**对"声称成功但未真实计算"的证据无任何真实性核验**。工具只要把 `status` 标成 `success` 并填入高分，即可获得通过。这正是 CoE Audit「分数核验」要解决的问题，本系统缺失。

### 3.2 验证 2：科学服务-方法代码对齐

**构造用例**：让 `_query_m1` 的 adapter 返回"无法识别化合物"（模拟真实引擎未命中），观察 fallback。

- 结果：静默回退到内置文献库，返回分子量 46.069 / 沸点 351.44K，`source` 标为 `DIPPR(内置)`
- 关联发现：真实引擎（chemicals 1.5.2）可用，但用 `identifier='ethanol'`（化合物名）调用时返回"无法识别化合物"——adapter 需要 CAS/SMILES，而 `application.py` 传的是化合物名，**真实引擎实际上经常未命中，多数查询走了内置库**

**结论**：方法声明"优先委托 ChemicalsAdapter（真实库）"与实际情况不完全对齐：真实引擎未命中时静默回落，且 `source` 字段不区分"真实引擎计算"与"内置库兜底"，用户无从得知数值来源的真实性层级。CoE Audit 的「方法-代码对齐」在其 `evidence_mapper` 中未体现。

### 3.3 验证 3：文献调研-引用核验

**构造用例**：真实调用 `LiteratureResearcherAgent.search`（仅开 WebAPI 源）。

- 结果：返回 5 条，其中 **4 条是 Crossref 的审稿评论**（`Review for "Intergranular to Transgranular Lithium Filamenta..."`，DOI 形如 `10.1039/d6ta00099a/v1/review2`），仅 1 条是正式论文；Semantic Scholar 被 429 限流
- 引用本身来自真实 API，**可溯源**（无幽灵引用）✅

**结论**：引用通道真实、可溯源，无幽灵引用，优于 `LLMKnowledgeRetriever` 的纯记忆式检索。但**无结果质量过滤/引用核验**：审稿评论、审查记录等非正式记录会混入结果，直通下游。Biomni 的参照价值在此体现——Biomni 用 `arxiv`/`pymed`/`scholarly` 检索后直接以论文元数据返回，且本地 `KnowHowLoader` 对协议类文档带元数据索引，可控性更强。

## 4. 借鉴价值排序与落地优先级

### 4.1 借鉴价值排序（高→低）

| 排序 | 借鉴点 | 来源 | 本系统现状 | 借鉴价值 |
|---|---|---|---|---|
| 1 | **CoE Audit 事后自动化审计**（分数核验/方法-代码对齐/引用核验） | Science One | `evals` 已有 golden set 回放，但偏"结果正确性"，无"证据链完整性"审计 | **高**（架构同构，落地成本低） |
| 2 | **独立声明核验器（Claim Verifier）**：成稿/产出前逐条核对声明与证据源，保守改写而非删除 | Science One | 无对应机制；委员会打分卡直接采信 | **高**（补上证据真实性缺口） |
| 3 | **声明→证据「产生时绑定」**：声明产生那一刻就构建证据链 | Science One | `EvidencePackage` 已实现"产生时绑定"，但 `source` 不区分真实/兜底 | **中高**（补强现有结构） |
| 4 | **文献 API 锚定 + 结果质量过滤**：引用核验、剔除审稿评论等噪音 | Science One + Biomni | 多源检索已真实，但无过滤/核验 | **中高** |
| 5 | **本地协议/知识文档索引（KnowHowLoader）**：带元数据检索本地权威资料 | Biomni | 有 `LocalKnowledgeBaseRetriever`，但无结构化元数据索引 | **中** |
| 6 | **全文级证据抽取**（PDF 全文/网页正文追溯） | Biomni | 无全文抽取，仅摘要级 | **中低** |

### 4.2 落地优先级建议（若未来立项改造）

按"补最关键的断裂 + 成本最低"排序：

1. **P1｜信任分级重构 `source`**：在 `EvidencePackage`/`evidence_mapper` 中区分证据来源层级（真实引擎计算 / 内置库兜底 / LLM 生成），并在前端展示。改动小、收益直接，是证据真实性基础设施。
2. **P1｜引入声明核验器**：在委员会 `CommitteeVerifier` 前增加"证据真实性核验"——对 `status='success'` 的证据校验其是否存在真实运行记录（复用 `run_id`/`artifact` 落库），而非只信 `score`。直接关闭验证1的缺口。
3. **P2｜CoE Audit 自动化审计**：扩展 `evals`，新增"证据链完整性"审计维度（抽查 N 条声明，反向核对其证据是否真实落库、方法是否对齐、引用是否可查）。与现有 golden set 机制复用，成本可控。
4. **P2｜文献检索结果质量过滤**：过滤审稿评论/审查记录等非正式条目，优先保留 peer-review 正式论文；可借鉴 Biomni 直接用 arxiv/PubMed 元数据的方式。
5. **P3｜方法-代码对齐增强**：科学服务 adapter 未命中时，`source` 明确标注"内置库兜底"而非 `DIPPR(内置)`，并可记录兜底原因。

---

## 5. 结论

Science One 对本系统的借鉴价值**成立**，且主要体现在**架构层思想**：它的"可验证性必须是一等架构约束、在声明产生那一刻就构建证据链"与本系统已有的 `EvidencePackage`+`ProvenanceGraph`+`AuditStore` 骨架方向一致，但本系统在**证据真实性核验**和**事后审计**两个维度未闭环。文章+Biomni 提供了可对照的补齐路径。若按 4.2 的 P1 两项先行，即以最低成本显著提升本系统产出的可验证性。
